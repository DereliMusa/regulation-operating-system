## What shipped

### CI/CD (`.github/workflows/`)

- **`ci.yml`** — on push to `main`/`dev` and PRs to `main`: `actions/checkout` + `setup-node@22`
  (npm cache) -> `npm ci` -> `npm run lint` -> `npm run typecheck` -> `npm run test` ->
  `npm run build`. Typecheck was added beyond the doc's original "lint + test + build" because it is
  part of the project's standing quality gate (every prior session ran it). The build step gets a
  throwaway `NUXT_SESSION_PASSWORD` (build-time only).
- **`deploy.yml`** — on push to `main`: buildx -> GHCR login (`GITHUB_TOKEN`) -> `metadata-action`
  (`latest` + short-SHA tags, auto-lowercased repo) -> `build-push-action` (GHA cache) -> a Coolify
  redeploy `curl` that **self-skips when `COOLIFY_WEBHOOK`/`COOLIFY_TOKEN` are unset** (job-level env
  so the `if:` can read it), so the image still builds/pushes before the host is wired up.

### Docker

- **`Dockerfile`** — multi-stage `node:22-alpine`.
  - Build stage: `apk add python3 make g++` (better-sqlite3 native build on musl), then **copy the
    full source before `npm ci`** so the `postinstall: nuxt prepare` hook has nuxt.config + app/, and
    better-sqlite3's install-time compile runs (`--ignore-scripts` is not usable — it would skip that
    compile). Then `npm run build`.
  - Runtime stage: `apk add libstdc++` (links the native binary), `NODE_ENV=production` + `PORT`/
    `HOST` + `DATABASE_PATH=/app/.data/certra.db`, `COPY --from=build .output`, and — the S2 finding —
    **`COPY --from=build server/database/migrations`** to the same relative path so `createDb()` (which
    resolves them from `process.cwd()`) finds them at boot. Runs as non-root `node`; `.data` is a
    `VOLUME`; a `HEALTHCHECK` uses Node's built-in `fetch`.
- **`.dockerignore`** — keeps `node_modules`/`.nuxt`/`.output`/`.data`/`.env`/`SDLC`/`eski-veriler`
  out of the build context (source `.output`/`.data` are regenerated, never leaked in).
- **`docker-compose.yml`** — runs the production image locally with a named volume on `/app/.data`
  (demonstrates the persistence requirement from `deployment.md`) and requires `NUXT_SESSION_PASSWORD`.

### Coverage

- Added `@vitest/coverage-v8`, a `test:coverage` script, and coverage config in `vitest.config.ts`:
  provider v8, `include` scoped to `server/utils` + `app/utils` (the pure business logic the MVP's
  critical paths run through), `db.ts` and `__tests__` excluded, **60% thresholds**. This makes
  "coverage check" a real pass/fail gate on the tested logic rather than framework glue.
