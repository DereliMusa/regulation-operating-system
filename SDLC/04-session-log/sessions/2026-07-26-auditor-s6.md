# Session 2026-07-26 — S6 Auditor Simulation

Continued the same day after closing out S5. The owner said "devam et" (continue), so built
S6 — Auditor Simulation (FR-AUD-1..2) — the product's headline "pre-audit gap detection" feature.

## What shipped

### Rule engine (mock AI)

- `shared/types/auditor.ts` extended with the ephemeral simulation contract (`SimulationFinding`,
  `SimulationSummary`, `AuditorSimulationResult`), kept distinct from the persisted
  `AuditorFinding` DB row (which the dashboard reads).
- `server/utils/auditorRules.ts` — pure `runAuditorSimulation(input)` decomposed into
  `gsprFindings` / `riskFindings` / `portfolioFindings`. Deterministic rules an NB reviewer would
  raise: GSPR missing = critical, partial = major (and a `no GSPR matrix` critical when empty); an
  unmitigated critical/major risk = critical/major; a mitigated risk with no verification ref =
  minor (and `no risk register` major when empty); overall readiness < 70% = major. Findings sorted
  most-severe first, with a pass/fail flag and a severity summary. Behind a stable interface for
  the Phase 1 Claude swap (ADR-005).
- `server/api/auditor/simulate.post.ts` — Zod-validated `{ technicalFileId }`, auth-protected by
  the default middleware, loads the file via `getTechnicalFileDetail` (404 if missing), returns
  the result.
- `server/utils/__tests__/auditorRules.test.ts` — 4 seed-derived tests: CardioGuard (100%) passes
  clean; GlucoCheck (deficiency) yields 3 critical + 3 major, critical-first, with references;
  OrthoFix flags RISK-040 (mitigated, no verification) as minor; an empty file yields the
  no-GSPR / no-risk findings.

### UI + export

- `app/utils/auditorReport.ts` — pure `buildAuditorReportMarkdown(result)` (unit-tested in
  `app/utils/__tests__/auditorReport.test.ts`), the MVP's Markdown export (no server-side PDF —
  see `storage-and-reports.md`).
- `app/components/technical-file/AuditorSimulation.vue` — a new **Auditor sim** tab on the
  technical-file detail. Runs the engine on mount (deterministic, so re-running is stable), with an
  AI-washed header honestly labelled "mock AI ... not a regulatory determination" (NFR-INTEG-1), a
  green pass banner or a severity-count summary + findings list (SeverityBadge, TraceabilityChip
  for the GSPR/RISK ref, recommendation). **Export report** builds the Markdown and downloads it
  client-side.

## Design decisions

- **Findings are ephemeral** (computed live per run, not persisted). The seeded `auditor_findings`
  table still backs the dashboard's "open findings". This keeps the simulation a deterministic
  what-if preview and avoids churning the audit trail; persistence can come later if wanted.
- **Home is a 4th detail tab**, not a separate route — `scope.md` frames Auditor Simulation as an
  action from within a technical file, and the tabbed detail is its natural host.
- **Export = Markdown download** (satisfies FR-AUD-2's "PDF/Markdown"); the printable-HTML
  print-to-PDF view stays a follow-up.
- **Readiness threshold 70%** for the file-level finding — keeps the ~78/88% seeded files out of
  it while flagging the 42/15% ones.
