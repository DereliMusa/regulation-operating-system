# Session 2026-07-26 — S7 Standalone module screens + audit auto-write

Third sprint of the day (after S5 and S6). The owner said "devam et", so built S7 — the four
seed-driven module screens (FR-RISK-2, FR-CER-1, FR-PMS-1, FR-LOG-1/2) and the audit-log
infrastructure that auto-writes on every mutation. This completes all MVP app + marketing screens;
only S9 (CI/CD + Docker) remains.

## What shipped

### Audit log (FR-LOG-1/2)

- `server/utils/auditLog.ts` — `writeAuditLog(db, entry)` records one activity-trail row;
  `getAuditLogView(db, filters)` returns entries newest-first with actor/impact/search filtering and
  KPI cards (total, high-impact, AI actions, last-7-days) computed over the whole log.
- **Auto-write wired into all eight S5 mutation routes** (technical-file / GSPR / risk
  create/update/delete): each route reads the session user and calls `writeAuditLog` with the action,
  impact, and entity ref. `deleteGspr` / `deleteRisk` now return the deleted ref so the entry is
  meaningful. This resolves the S5 deferral.
- `server/api/audit-log/index.get.ts`; the new `AuditLogKpis` / `AuditLogView` types added to the
  pre-existing `shared/types/audit-log.ts` (see "gotcha" below).
- `app/pages/audit-log.vue` — KPI cards, actor/impact filters, and the activity table (actor icon,
  action + description, entity ref, impact badge, timestamp).

### The three read-mostly screens

- **Risk Management (FR-RISK-2):** `server/utils/riskRegister.ts` (all risks joined to device,
  most-severe first, severity/status summary) -> `GET /api/risk` -> `risk.vue` (summary cards +
  register table).
- **Clinical Evaluation (FR-CER-1):** `server/utils/clinical.ts` (evidence + summary + AI-summary
  suggestions ranked by confidence) -> `GET /api/clinical` -> `clinical-evaluation.vue` (cards,
  literature table, AI-suggestions panel).
- **Post-Market (FR-PMS-1):** `server/utils/postMarket.ts` (plans soonest-due first with
  days-remaining, type / overdue / due-soon summary) -> `GET /api/post-market` -> `post-market.vue`
  (milestone timeline + plans table + AI insight).

All three utils are pure and unit-tested (`moduleOverviews.test.ts`), like the dashboard aggregation.

## Gotcha found: duplicate shared type file

A `shared/types/audit-log.ts` already existed (from S1) exporting `AuditLogEntry` / `AuditActorType`
/ `AuditImpact`. I first created a second `shared/types/audit.ts` with the same names; Nuxt's
auto-import warned about the duplicate exports (compiled, but noisy and wrong). Consolidated: added
the new KPI/view types to the existing `audit-log.ts`, deleted `audit.ts`, and pointed the imports
there. Lesson: check for an existing `shared/types/*` before adding a new one.
